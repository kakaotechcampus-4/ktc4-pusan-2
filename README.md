## Git 컨벤션

같은 작업이 세 곳에서 각각 이렇게 적힌다.

| 위치 | 형식 | 예 |
|---|---|---|
| 브랜치 | `타입/영역-작업명` | `feat/be-login-api` |
| PR 제목 | `[영역] 타입: 작업 내용` | `[BE] feat: 로그인 API 구현` |
| 커밋 메시지 | `타입(영역): 작업 내용` | `feat(be): 로그인 API 구현` |

**PR 제목의 영역만 대문자**(`[BE]`)이고, 브랜치와 커밋은 소문자(`be`)다.

### 타입

| 타입 | 쓰는 때 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작을 바꾸지 않는 구조 개선 |
| `test` | 테스트 추가·수정 |
| `docs` | 문서 |
| `chore` | 설정·의존성·빌드 등 그 외 |

### 영역

| 코드 | 범위 |
|---|---|
| `fe` | 프론트엔드 |
| `be` | 백엔드 |
| `ai` | AI |

### 브랜치 — `타입/영역-작업명`

```
feat/fe-login-page
feat/be-login-api
feat/ai-feedback
```

작업명은 소문자와 하이픈으로 쓴다. 
팀 내부 작업은 `develop` 에서 따고 `develop` 으로 PR 을 보낸다.
`main` 은 멘토 리뷰용이다.

### PR 제목 — `[영역] 타입: 작업 내용`

```
[BE] feat: 로그인 API 구현
```

### 커밋 메시지 — `타입(영역): 작업 내용`

```
feat(be): 로그인 API 구현
```
