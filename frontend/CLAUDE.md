# 피치코치 프론트엔드

발표 리허설 코칭 웹앱. 사용자가 발표 자료와 대본을 올리고, 브라우저에서 리허설하면,
시선·말하기 지표를 분석해 다음 Take에서 고칠 것 한 가지를 제안합니다.

**핵심 철학 — 점수가 아니라 Take 간 변화.** 총점을 매기지 않습니다.
"이번이 지난번보다 무엇이 나아졌나"가 모든 화면의 기준입니다.

---

## 반드시 지켜야 할 결정 사항

이미 팀에서 합의했거나 근거가 확실한 것들입니다. 이유 없이 바꾸지 마세요.

### 1. 카메라는 온디바이스 — 영상은 서버로 가지 않습니다

시선 분석은 브라우저 안에서만 합니다. 카메라 영상 프레임은 **어떤 형태로도 서버에 전송되지 않습니다.**

| 대상 | 처리 | 서버 전송 |
| --- | --- | --- |
| 카메라 영상 | 브라우저 워커 | 없음 |
| 시선 구간(계산 결과) | 구간 압축 후 | `POST /complete` |
| Calibration 기준 벡터 | IndexedDB | 없음 (품질 요약만) |
| 마이크 오디오 | 녹음 후 업로드 | 있음 (STT 필요) |

**"온디바이스"가 전부 로컬이라는 뜻은 아닙니다.** 카메라는 100% 로컬, 마이크는 업로드입니다.

따라오는 결과:
- 서버는 시선 값을 재계산할 수 없습니다. 형식 검증만 합니다 (`422 INVALID_SEGMENTS`).
- 과거 Take를 다시 분석할 수 없습니다. 숫자는 종료 시점에 영구 고정됩니다.
- 그래서 `gazeEngineVersion`과 `measuredMs`가 **필수**입니다.

### 2. 시선 판정은 3값입니다 — 4분할이 아닙니다

```ts
type GazeZone = 'CAMERA' | 'BOTTOM' | 'UNCERTAIN';
```

`SLIDE`와 `SCRIPT`를 나누려고 하지 마세요.

물리적으로 불가능해서가 아니라 **신뢰성과 범위 판단**입니다.
`CAMERA`↔`BOTTOM`은 고개도 함께 움직여 head pose와 시선 벡터가 서로를 보강하지만,
같은 화면 안에서 좌우로 옮겨볼 때는 고개가 안 움직여 head pose 신호가 사라지고
웹캠에서 가장 불안정한 홍채 신호만 남습니다. 그리고 제품이 그걸 필요로 하지 않습니다 —
대본 의존도의 근거는 시선이 아니라 `scriptSimilarity`입니다.

**2분할로 확정했습니다.** AI팀 실측을 기다리지 않습니다 -
카메라와 화면 사이가 이 제품의 주 지표인데, 3분할로 가면 그 각도 차가 10도에서 7도로 줄어
**정작 중요한 판정이 나빠집니다.**

그래서 **대본 의존도의 주근거는 시선이 아니라 `scriptSimilarity`** 입니다 —
STT 전사와 대본 원문의 유사도. "아래를 봤다"는 간접 증거지만
"말한 내용이 대본과 91% 같다"는 직접 증거입니다.

### 3. 판정 주기는 1초입니다

Temporal Voting/EMA가 1초 단위라서:
- `gazeSegments`의 최소 구간 길이가 1,000ms
- 실시간 코치 규칙의 최소 반응 시간이 1초
- **화면 테두리는 초당 한 번만 갱신됩니다.** 프레임마다 setState 하지 마세요

테두리 3색이 시선 표시의 전부입니다 - 배지를 따로 두지 않습니다.

| 상태 | 색 | 형태 |
| --- | --- | --- |
| 청중(카메라) | `#6B9E78` | solid 2px |
| 화면(대본·슬라이드) | `#D9A441` | solid 5px |
| 판정 불가 | `#C0392B` | **dashed** 5px |

판정 불가만 점선인 이유 - 색만 다르면 색각 이상에서 셋이 구분되지 않습니다.
가장 중요한 상태(데이터가 유실되는 중)에 형태 차이를 줍니다.
깜빡임을 막으려고 3초 히스테리시스와 400ms 크로스페이드를 겁니다.

### 4. 리허설 중 서버는 **덤**입니다 — 브라우저가 원본입니다

BE가 WebSocket을 쓰기로 확정돼서, 발표 중에 음성이 서버로 실시간으로 흘러갑니다.
그래야 말하기 속도·군더더기·평가 기준 이행 여부를 발표가 끝나기 전에 알려줄 수 있습니다.

**그런데 이걸 연습의 전제로 삼지 않습니다.**

```
화면이 쓸 자료   → P4에서 한 번에 다 받아둔다
모든 기록        → IndexedDB에 쌓인다             ★ 원본
음성             → MediaRecorder로 로컬 저장       ★ 원본
                 → AudioWorklet PCM으로 WS 전송     덤
```

그래서 코치가 **2단**입니다.

| | 무엇 | 끊기면 |
| --- | --- | --- |
| **1단 · 브라우저** | 시선 · 음량 · 침묵 · 시간 · 슬라이드 | 계속 돈다 |
| **2단 · 서버** | 속도 · 군더더기 · 대본 일치 · 평가 기준 | **이것만 조용해진다** |

끊기면 작은 안내 한 줄만 띄우고 발표는 그대로 갑니다. 재연결은 지수 백오프 3회까지.
끊긴 구간의 음성도 로컬에 남아 있으니 발표 후 배치로 다시 처리합니다 —
**실시간만 잠깐 죽고 리포트는 온전합니다.**

`MediaRecorder`가 뱉는 webm/opus는 스트리밍 STT에 못 씁니다.
서버로 보내는 경로는 `AudioWorklet` -> Int16 16kHz 다운샘플입니다.
worklet 파일은 `public/worklets/`에 평범한 JS로 둡니다 - 번들러를 태우지 않습니다.

### 5. 시간 필드 셋의 관계

```
measuredMs + uncertainMs === trackedMs
cameraMs   + bottomMs    === measuredMs
```

**모든 시선 퍼센트의 분모는 `measuredMs`입니다.** `durationMs`로 나누면
카메라가 꺼져 있던 시간까지 "안 봤다"로 계산됩니다.

### 6. 없음은 `null`이고 키는 유지합니다

시선 측정이 제외된 Take의 `cameraMs`는 **`0`이 아니라 `null`** 입니다.
`0`으로 두면 화면에 "청중을 0% 봤습니다"가 뜹니다. 실제로는 측정을 안 한 건데요.

타입에서 `?`(optional)를 쓰지 말고 `| null`을 쓰세요.

### 7. 스타일 — Tailwind, 단 리허설 무대만 예외

| 어디 | 무엇으로 | 왜 |
| --- | --- | --- |
| 화면 18개 | **Tailwind** | 평범한 폼·카드·목록이다. 빠른 게 이긴다 |
| 리허설 무대 | **`Stage/stage.css`** | 레이아웃 자체가 명세라 주석이 붙어야 한다 |

토큰은 `src/index.css`의 `@theme` 한 곳에만 있습니다.
`bg-[#EDE6DD]` 같은 임의값이 보이면 리뷰에서 잡습니다.

**`--spacing-script-*` 네 값은 디자인이 아니라 계측 조건입니다.**
대본 영역 높이가 바뀌면 시선 각도가 바뀌고 Calibration 기준이 어긋납니다.
그러면 그 시점 이전 Take와 비교가 불가능해집니다. 고치려면 팀 합의가 필요합니다.

시선 테두리는 **React를 거치지 않습니다** — `stageRef.current.dataset.gaze = zone` 한 줄이고
색·두께·점선은 `stage.css`가 `[data-gaze=...]`로 받습니다.
`/dev/stage`에서 확인할 수 있습니다. 시선 버튼을 눌러도 렌더 카운터가 안 올라가야 정상입니다.

### 8. Take는 준비 화면의 시작 CTA에서만 생깁니다

```
/pitch/:pitchId/prepare      ← 아직 Take가 없다
    시작 CTA
      POST /takes                    takeId 발급 (clientSessionId 멱등키)
      POST /takes/{id}/calibration   품질 요약만
      WS   /ws/takes/{id}
/takes/:takeId/rehearsal     ← 여기부터 takeId
```

홈과 리포트의 `Take N 시작`은 **이동만 합니다.** 거기서 `POST /takes`를 부르면
준비 화면에서 이탈한 만큼 빈 Take가 쌓이고 `takeNumber`가 실제 연습 횟수와 어긋납니다.

Take가 스냅샷하는 값(`mode`·`scriptMode`·자료/대본/기준 버전)이 준비 화면에서 정해지고,
Calibration과 WebSocket을 붙일 `takeId`가 리허설 직전에 필요하기 때문입니다.

## 구조

```
src/
  app/          라우팅. 화면 19개 + 모달 3개
  shared/
    ui/         공용 컴포넌트 (버튼·모달·빈 상태·스켈레톤)
    lib/        순수 함수 (시계, 구간 압축) — 여기 있는 건 테스트가 쉽습니다
    api/        쿼리 훅
  features/
    auth/       로그인·토큰
    pitch/      Pitch 생성·수정·목록
    rehearsal/  ★ 리허설. 난이도 최상 (Track A)
    report/     리포트·비교·Best Take
  workers/      시선 워커. 메인 스레드에서 격리
  mocks/        MSW. 명세 8-4의 JSON 그대로
  types/        API 타입. 명세가 바뀌면 여기부터
```

**Track A** = `rehearsal/` + `workers/` — 한 사람이 전담합니다.
**Track B** = 나머지 — 화면 수는 많지만 대부분 CRUD입니다.

## 작업 방식

### 화면 하나 만드는 순서 (Track B)

1. 명세 8-4의 응답을 `types/api.ts`에 타입으로
2. 그 JSON을 `mocks/handlers.ts`에 그대로
3. 쿼리 훅 (`shared/api/`)
4. 화면 컴포넌트
5. **상태 붙이기 — 로딩·빈·에러·부분 실패.** 명세 8-3 표가 체크리스트입니다
6. (W8) 목만 걷어냄

5번을 나중으로 미루지 마세요. 상태 10개가 전부 마지막 주로 몰립니다.

### 리허설 (Track A)

층을 아래에서 위로 쌓습니다. 각 층이 도는 걸 확인하고 다음으로 갑니다.

```
카메라 스트림 → 워커에 프레임 → 워커 안에서 판정
  → 1초마다 결과만 메인으로 → ref/스토어 저장 → 렌더(1Hz) → 종료 시 조립
```

**워커 경계가 성능의 전부입니다.** 프레임은 워커로 들어가고 1초 판정만 나옵니다.
원시 좌표를 메인 스레드로 넘기기 시작하면 그 순간 끝납니다.

### 상태를 어디에 둘지

| | 무엇 | 도구 |
| --- | --- | --- |
| 서버에서 온 것 | Pitch, 리포트, 홈 | TanStack Query |
| 화면에 보이는 리허설 상태 | phase, 슬라이드 번호, 코치 메시지 | Zustand |
| 프레임 단위 고빈도 값 | 시선 원시 좌표, 오디오 RMS | `useRef` — **상태로 두면 안 됨** |

## 개발 중 함정

**모델 파일을 CDN에서 받지 마세요.** MediaPipe WASM과 gaze 가중치는 `public/models/`에
두고 Cache API로 캐싱합니다. 시연장 와이파이가 느리면 발표가 안 됩니다.

**타이머는 `performance.now()` 기준으로.** `setInterval` 카운트를 올리면
백그라운드 탭에서 시간이 실제보다 적게 흐릅니다. `shared/lib/clock.ts` 참고.

**카메라 HMR.** `useCameraStream`의 `import.meta.hot` 블록을 지우지 마세요.
없으면 저장할 때마다 카메라가 물려서 브라우저를 껐다 켜야 합니다.

## 명령어

```bash
npm run dev          # 목 서버 위에서 개발
npm run dev:lan      # LAN HTTPS - 카메라를 다른 기기에서 테스트할 때
npm run build        # 타입 체크 + 프로덕션 빌드
npm run typecheck    # 타입만
npm run test         # 순수 로직 테스트
npm run lint         # oxlint
```

**세팅이 끝났는지 확인하는 네 가지**

1. `npm run dev` -> 화면이 뜬다
2. 콘솔에 `crossOriginIsolated` -> **`true`** (COOP/COEP가 먹었다는 증거)
3. `npm run dev:lan` -> 다른 기기에서 **카메라 권한 팝업이 뜬다**
4. `/dev/stage` -> 시선 버튼을 눌러도 렌더 카운터가 안 올라간다

2번을 꼭 하세요. 헤더 오타는 에러를 안 냅니다.
몇 주 뒤 워커에서 `SharedArrayBuffer is not defined`가 났을 때 원인을 못 찾습니다.

목을 끄고 실서버로 붙일 때: `.env.local`에 `VITE_USE_MOCK=false`
