# #540 서비스 만족도 리뷰 — FE 목 구현

이 문서는 FE 초안이며 BE 합의나 확정 API 명세가 아니다. AI 분석 결과의 `report.review`와 별개다.

## 구현한 범위

- 개발 모드이며 `VITE_USE_MOCK`이 `false`가 아닐 때만 활성화한다. 운영 빌드·실서버 개발에서는 팝업과 요청을 모두 차단한다.
- Take 종료 전송 성공 후 같은 탭의 sessionStorage에 노출 후보를 기록한다. 종료 재시도 성공도 포함한다.
- 분석 단계 DONE, Take COMPLETED, AI 리뷰 DONE 및 본문이 있는 리포트에서 하단 ‘내 피치로’ 또는 ‘Take N 연습하기’를 누르면 표시한다. 조회 오류·분석 중·실패·보류에는 표시하지 않는다.
- 모달은 1~5점 라디오, 제출, 닫기, 나중에를 제공한다. 별점 선택 전·전송 중 제출을 막고 실패 시 선택을 유지하며 재시도한다.
- 성공·닫기·나중에·Escape는 원래 목적지로 이동한다. 전송 중에도 닫을 수 있다. Take 생성은 기존 장치 점검에서만 한다.
- 네이티브 dialog로 포커스 가두기와 Escape를 처리하고 배경 스크롤을 잠근다. 해제 시 기존 포커스 복귀를 시도한다.
- 임시 정책: 팝업을 여는 순간 같은 Take의 후보를 소비한다. 팝업 없이 리포트에서 이탈해도 미사용 후보를 만료시키므로 상단 홈 이동·뒤로가기 후 과거 리포트 재방문에 요청하지 않는다. 같은 탭 새로고침·재방문에 반복 노출하지 않는다. 새 Take는 다시 후보가 된다. 제출/나중에를 구별한 장기 정책과 기기 간 동기화는 구현하지 않았다.

## 목 전용 API

`POST /api/mock/service-reviews/:takeId`

요청: `{ "rating": 1 }` (정수 1~5). 응답: `{ "take_id": "…", "rating": 1 }`.

범위를 벗어나면 422 INVALID_RATING. 같은 Take 재요청은 첫 저장값을 반환한다. 저장은 MSW 메모리 안에만 있어 페이지를 새로고침하면 사라진다. 실제 만족도를 수집·보관하는 기능은 아니다.

Take id `t-review-retry`는 최초 전송만 503으로 실패하고 재시도하면 성공한다. 별점에 따른 경로 차이는 없다.

## BE 및 제품 담당과 합의할 항목

| 항목 | 결정할 내용 |
| --- | --- |
| 목적과 운영 조회 | 내부 만족도 수집 목적, 운영자 조회 위치·권한 |
| 저장 계약 | 확정 URL·메서드·요청/응답·오류 코드, 의견 입력 여부, Take 연결 여부 |
| 사용자 식별·중복 | 인증 사용자 기준 1회인지 Take별인지, 서버 검증과 멱등 처리, 제출 중 닫은 뒤 성공한 요청 처리 |
| 노출 트리거 | 리포트 하단 두 버튼 범위, AI 리뷰 실패/생략 상태도 대상인지, 과거 리포트와 신규 완료 구별 근거 |
| 재노출 | 최초 요청 조건, 제출 후 중단 여부, 나중에 이후 간격·횟수 |
| 상태 저장 | shown/submitted/deferred 구분, 서버 상태 조회, 여러 탭·기기·로그인 계정 전환 시 유지 |

실 API 연동 전에 위 계약을 이슈에 기록하고 목 전용 경로·세션 정책을 교체해야 한다. 현재 sessionStorage는 계정별 저장이 아니므로 최종 노출 상태로 사용하면 안 된다.

## 수동 확인 경로

목 환경에서 장치 점검 → Take 종료 → 분석 완료 → 리포트 하단 이동 버튼. 제출·나중에 각각 목적지가 유지되는지 확인한다. 단순 `/takes/t3` 직접 진입은 팝업을 표시하지 않는다.

리허설 없이 목 팝업만 확인하려면 개발자 콘솔에서 `sessionStorage.setItem('pitchcoach:review-preview:t3', 'ready')` 후 `/takes/t3`에 진입하고 하단 버튼을 누른다. 재시도는 같은 방법으로 `t-review-retry`를 사용한다. 해당 id는 리포트 목이 분석 완료가 될 때까지 기다린다.

Chrome에서 320·375·768px의 모달·로고·닫기 버튼이 가용 폭 안에 들어가고, 헤더 겹침·수평 넘침이 없으며 닫기 후 홈으로 이동하는 것을 확인했다. 키보드 포커스 순환·라디오 방향키·스크린리더 안내는 추가 확인한다.

## PR #560 P2 회귀 검증

- 상단 홈 링크로 이탈 후 기록 다시 열기, 뒤로가기 후 앞으로가기로 돌아오기 모두 팝업을 요청하지 않는 테스트를 추가했다.
- 같은 Take의 만료된 후보는 종료 재처리로 다시 활성화되지 않으며 다음 Take는 정상 노출된다.
- 리포트 흐름 테스트 전체를 StrictMode에서 실행해 effect 재실행만으로 정상 첫 노출이 사라지지 않는 것을 확인한다.
- `scripts/service-review-layout.check.cjs`는 실제 Chrome에서 320·375·768px의 수평 넘침·모달 화면 이탈·헤더 겹침·닫기 버튼 영역과 홈 이동을 검사한다.

브라우저 회귀 검사 실행 위치는 `frontend/`다. 먼저 `VITE_USE_MOCK=true`, `VITE_MOCK_SESSION=true`로 `npm run dev -- --port 3012`를 실행한다. Playwright와 Chrome이 필요하며 Playwright가 별도 런타임에 있으면 `NODE_PATH`를 해당 node_modules로 지정한다. 이후 `node scripts/service-review-layout.check.cjs`를 실행한다. 다른 서버 주소를 사용하면 `REVIEW_BASE_URL`을 지정한다. 이번 검증에서는 제공된 번들 Playwright와 설치된 Chrome을 사용해 세 화면 크기 모두 통과했다.
