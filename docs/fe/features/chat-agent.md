# 대화형 에이전트 (FE)

> **기준 범위**: 대화형 에이전트의 화면(FE) 쪽 문서입니다. 에이전트가 하는 일, BE · AI 사이의 계약, 안내 문구의 원본은 [docs/ai/features/chat-agent.md](../../ai/features/chat-agent.md)(이하 "AI 문서", 특히 12절)가 기준입니다. 이 문서에는 FE가 그것을 화면에 붙인 방식과 FE에만 있는 규칙만 적습니다. 둘이 다르면 AI 문서를 따르고 이 문서를 고칩니다.
>
> **한 줄 요약**: 질문을 보내고 실행 상태를 1 · 2초마다 조회해 답을 그리며, 버튼을 띄울지는 BE의 사용 가능 여부가 정합니다.
>
> **기준값**: 경로는 `shared/api/chatPaths.ts`, 조회 간격 · 재시도 · 제한 시간은 `chatTransport.ts` · `chatAvailability.ts` · `chatTyping.ts`의 상수가 기준입니다. 8절의 숫자는 그 값을 옮긴 것입니다.

AI 문서의 절은 "AI 12-4 F3"처럼 가리킵니다. `F`번호는 AI 문서 12-4 "FE 할 일" 표의 번호입니다(예: F1 버튼 · 팝업, F8 오류 · 꺼짐 · 한도 안내, F9 E2E 시험, F15 '기억 없이' 대화). `#123`은 GitHub 이슈 · PR 번호입니다.

## 0. 한눈에 보기

- 화면 오른쪽 아래의 **새미나이(Semini)** 버튼을 누르면 오른쪽에 대화 패널이 열립니다. 패널을 연 동안 런처를 숨기고, 패널 내부 닫기 또는 Esc로 닫으면 런처로 초점이 돌아옵니다. 너비 1440px 이상에서는 400px 패널만큼 헤더와 본문이 줄고, 그보다 좁으면 패널이 화면 위에 겹쳐 표시됩니다.
- FE는 **질문을 보내고, 실행 상태를 조회해(실행 중 1초 · 그 밖 2초마다) 답을 그리는 일**만 합니다. 판단 · 문구 · 도구 실행은 BE · AI가 합니다.
- 버튼을 띄울지는 BE가 정합니다(`GET /api/chat/availability`). FE에는 빌드 스위치가 없습니다(#1073에서 FE 스위치를 없앰).
- 받은 응답은 그리기 전에 모양을 검사하고(`chatResponse.ts`), 검사를 통과하지 못한 부분은 그리지 않습니다.

## 1. 왜 필요한가 · 용어

사용자가 리포트 여러 장을 직접 비교하지 않아도, "계속 막히는 데 찾아 줘" 같은 질문으로 자기 연습 기록을 근거와 함께 볼 수 있게 합니다. 목적 · 범위는 AI 문서 0 · 1절을 봅니다.

| 용어 | 뜻 |
|---|---|
| 대화(conversation) | 질문 · 답이 쌓이는 묶음. 범위(전체 / 피치 하나)를 가집니다 |
| 실행(run) | 질문 하나에 대한 처리 한 번. `QUEUED` → `RUNNING` → (`WAITING_APPROVAL`) → 종결(`DONE` · `PARTIAL` · `REFUSED` · `FAILED` · `CANCELLED` · `EXPIRED`) |
| 범위(scope) | 에이전트가 볼 기록. 전체, 또는 피치 하나 |
| 화면 상태(screen) | 피치 만들기 · 수정 화면에서 입력 중인 값. 질문과 함께 보냅니다 |
| 카드 | 답 아래의 버튼 묶음. 목표 저장(되돌리기), 연습 준비, 승인 · 거절 확인 등 |
| 근거 칩 | 답 문장마다 붙는 출처 표시. 내 기록 · 화면 값 · 자료 |
| 답 문장(claim) | 답을 이루는 문장 한 줄. 종류(기록 · 자료 · 일반 조언 · 안내 등)와 근거를 함께 받습니다 |
| 이벤트 순번(`seq`) · 커서(`after_seq`) | 실행이 내보낸 진행 줄 · 답 문장의 순번. FE는 받은 마지막 순번 뒤의 것만 다시 묻습니다 |
| 요청 키(`client_request_id`) | 보내기마다 FE가 만드는 UUID. 같은 키로 다시 보내면 BE가 같은 요청으로 봐서 두 번 접수하지 않습니다(멱등) |
| '기억 없이' 대화 | 코칭 프로필을 읽지도 쓰지도 않는 대화. 대화 기록 · 요약은 그대로 보관됩니다. 새 대화에서 첫 메시지를 보내기 전에만 고릅니다(AI 12-4 F15) |

## 2. 화면 흐름

**버튼이 보이는 화면** — 허용 목록(`chatRoutes.ts`)에 있는 화면만입니다.

- 보임: `/` · `/pitches` · `/pitch/new` · `/pitch/:id/edit` · `/takes` · `/me` · `/about` · `/takes/:takeId` · `/takes/:takeId/processing` · `/takes/:takeId/confirm` · `/takes/:takeId/retry` (`chatRoutePatterns`가 기준)
- 안 보임: 장치 점검(`/pitch/:pitchId/device-check`), 발표 중(리허설 · 실전), 로그인 전, `/privacy` · `/terms` · `/unsupported` · `/dev/*` 등 그 밖의 모든 화면
- 새 화면에 띄우려면 목록에 직접 넣어야 합니다. 실수로 노출되지 않게 하려는 것입니다.

**대화창 머리줄**(`ChatPanelHeader.tsx`) — 제목(새미나이 · "Semini · AI 비서 앱")과 [새 대화] · [대화 목록] · [기억 설정] · [닫기] 버튼이 있습니다. 새 대화에서 첫 메시지를 보내기 전에는 '기억 없이 대화하기' 스위치도 보입니다. 선택 직후에는 스위치가 상태를 알려 주므로 배지를 중복 표시하지 않습니다. 전송·대화 생성을 시작하거나 기존 '기억 없이' 대화를 열면 스위치 대신 '기억 없이' 배지를 표시합니다. 새 대화에서는 선택과 배지를 초기화합니다. 기억 설정에서 코칭 프로필 기억을 꺼 두었으면 스위치가 잠깁니다.

**대화창 안의 세 화면** — 머리줄 버튼으로 바꿉니다.

| 화면 | 설명 |
|---|---|
| 메시지 | 기본 화면. 대화가 비어 있으면 새미나이 빈 대화 안내(`ChatEmptyState`)를 보입니다 |
| 대화 목록 | 지난 대화 고르기 · [지난 대화 더 보기]. '기억 없이' 대화에는 "· 기억 없이"가 붙습니다 |
| 기억 설정 | 입력칸을 숨깁니다. 쓰던 글은 남습니다 |

**닫기** — 닫기 버튼 또는 Esc.

- 닫아도 대화 상태는 스토어에 남아, 다시 열면 이어집니다.
- 허용 화면끼리 이동하면 열린 상태가 유지됩니다. 비허용 화면으로 이동하면 닫히고, 허용 화면으로 돌아와도 닫힌 상태에서 시작합니다. 다시 열면 이전 대화를 볼 수 있습니다.
- 761~1439px 오버레이는 본문 너비를 유지하되 화면에 **현재 보이는 헤더 영역** 아래에서 시작합니다. 일반 헤더가 스크롤로 화면 밖으로 사라지면 패널은 화면 맨 위까지 확장됩니다. 발표 생성·수정에서는 하단 고정 바의 **실제 높이** 위에서 끝납니다. 줄바꿈·화면 변경 때는 ResizeObserver로 높이를 다시 재고, 문서 스크롤 시 헤더 위치를 반영합니다. 분석 대기·대본 확인 노을 화면의 오른쪽 조작부는 패널 왼쪽으로 이동합니다.
- 너비 760px 이하에서는 오버레이가 열린 동안 배경 조작과 스크롤을 막습니다. Escape 또는 닫기 버튼으로 닫으면 열기 버튼으로 초점이 돌아갑니다.
- 화면별 런처의 기본 하단 여백은 홈·피치 목록 76px, 리포트(`/takes/:takeId`) 96px, 발표 생성·수정 88px, 그 외 32px입니다. 760px 이하의 생성·수정 화면에서는 버튼을 하단 16px에 둡니다. 펼친 채팅 오류 안내는 359px 이하에서 하단 192px, 360~760px에서 하단 144px로 올리고, 안내가 펼쳐진 동안에만 본문 아래 스크롤 여백을 늘려 마지막 조작부에 접근할 수 있도록 합니다.
- 모바일에서는 `body`의 넘침을 잠그되 `window.scrollY`를 보존합니다. 따라서 같은 화면에서 닫거나 패널을 연 채 다른 화면으로 이동해도 React Router `ScrollRestoration`이 앞뒤 화면의 실제 위치(0이 아닌 위치 포함)를 기록·복원합니다. `position: fixed` 방식이나 비공개 라우터 컨텍스트는 사용하지 않습니다.
- 대본 매핑과 슬라이드 확인 모달은 기존 뷰포트 기준 크기로 패널 위에 표시됩니다. 모달을 닫으면 패널의 이전 상태가 유지됩니다.
- 로그아웃하면 지웁니다.

## 5. BE 계약

경로는 `shared/api/chatPaths.ts` 한 곳에 있고, BE `module/chat/controller.py`에 맞춥니다. 모두 `/api/chat` 아래입니다.

| 경로 | 쓰는 곳 |
|---|---|
| `GET /availability` | 버튼을 띄울지. `{enabled: false}` 또는 `AGENT_DISABLED`면 숨깁니다 |
| `POST /conversations` · `POST /messages` | 대화 만들기(`{pitch_id, memory_off}`) · 질문 보내기. 보내면 실행 ID를 받습니다 |
| `GET /conversations` · `PATCH /conversations/{id}/scope` | 대화 목록(커서로 이어 읽기) · 범위 바꾸기 |
| `GET /conversations/{id}/messages` · `GET /conversations/{id}/run` | 메시지 목록 · 그 대화의 마지막 실행(끝났어도. 한 번도 없으면 `null`, 복원에 씀) |
| `GET /runs/{id}` · `POST /runs/{id}/cancel` | 실행 상태 조회 · 취소 |
| `POST /runs/{id}/actions/{actionId}/decision` · `.../undo` | 승인 · 거절, 되돌리기 |
| `GET · PUT /memory` · `DELETE /memory/items` · `DELETE /memory/items/{id}` | 기억 설정 · 항목 지우기 |

- 요청 · 응답의 경로 · 필드는 AI 문서 12-3, 오류 문구는 7-9가 기준입니다. FE 타입은 `src/types/chat.ts`입니다.
- BE에 아직 없는 것은 코드에 `(BE 미구현)`으로 표시하고 목만 흉내 냅니다. BE가 생기면 이 표시를 찾아 고칩니다. 지금 남은 것은 10절에 적습니다.

## 6. 처리 흐름

```
[보내기]  POST /messages ──▶ 실행 ID
              ▼
[조회]    GET /runs/{id}?after_seq=…   실행 중 1초 · 그 밖 2초마다
              │  WAITING_APPROVAL 이면 확인 카드 → [승인] · [거절]
              ▼
[종결]    메시지 목록을 다시 읽어 저장된 답으로 바꾸고, 상태별 안내를 붙임(7절)
```

**보내기**

- 접수를 15초 안에 확인하지 못하면 [다시 보내기] 또는 [다시 확인] 버튼을 띄웁니다.
- 자동으로 다시 보내지 않습니다. 사용자가 누르면 같은 `client_request_id`로 보내서, 두 번 접수되지 않습니다.

**조회**

- 응답의 `events`(진행 줄 · 답 문장)를 커서(`next_after_seq`) 뒤로만 받아 이어 붙입니다.
- 답 문장(`claim`)은 글자 효과 큐에 넣어 한 글자씩 그립니다.

**복원**

- 새로고침하면 sessionStorage에 둔 대화 ID로 그 대화의 마지막 실행(`GET /conversations/{id}/run`)을 다시 찾고, 아직 끝나지 않았으면 조회를 이어 갑니다.
- 화면 이동은 스토어가 그대로라 끊기지 않습니다.

**잠금**

- 보내는 동안 · 실행 중에는 입력칸과 답 아래 버튼을 잠그고, 잠긴 이유를 화면 낭독기가 읽습니다.
- 범위를 다시 골라야 하면(피치가 지워짐 등) 범위를 고를 때까지 보내지 않습니다.

## 7. 로딩 · 빈 · 오류 · 부분 실패

| 상황 | 화면 |
|---|---|
| 사용 가능 여부 조회 중 | 버튼을 숨깁니다. 5초 안에 답이 없으면 오류로 두고 2 · 4 · 8초 뒤 다시 묻습니다 |
| 사용 가능 여부 조회 실패(재시도까지) | 버튼은 보입니다. 열면 "새미나이를 불러오지 못했으니 다시 시도해 주세요." + [다시 시도]. 실패를 꺼짐으로 보지 않습니다 |
| 꺼짐(`enabled: false` · `AGENT_DISABLED`) | 버튼을 숨깁니다 |
| 이전 대화 불러오는 중 · 실패 | "이전 대화를 불러오고 있어요." · "대화를 불러오지 못했으니 다시 시도해 주세요." + [다시 시도] |
| 빈 대화 | 새미나이 빈 대화 안내(`ChatEmptyState`): "새미나이에게 물어보세요" · "발표 기록을 분석하거나 다음 연습을 준비할 수 있어요." 아래에 할 수 있는 일 · 질문 예시(`ChatAskHelp`)를 붙입니다. 예시를 누르면 그 문장을 바로 보냅니다 |
| 중간까지만 답함(`PARTIAL`) | "여기까지 확인했어요. 남은 일: …" + [이어서 확인] |
| 거절(`REFUSED`) | AI의 고정 문장이 답이고, 말풍선 밖 아래에 "이런 걸 도와드릴 수 있어요" · 할 수 있는 일 · 질문 예시(`ChatAskHelp`, AI 12-4 F8)를 붙입니다. 마지막 답이 거절이고 보내는 중이 아닐 때만 보여, 거절이 이어져도 안내가 쌓이지 않습니다. 보낼 수 없는 동안에는 예시 버튼이 잠깁니다 |
| 실패 · 만료 · 취소 | 상태별 안내(`chatNotices.ts`, AI 7-9 · 7-10 문구). 다시 보낼 수 있으면 [다시 보내기] |
| 오래 걸림 | 130초가 지나면 "결과 확인이 늦어지고 있으니 상태를 다시 확인해 주세요."와 [상태 확인], 조회는 30초 간격으로 늦춥니다 |
| 대화창이 그리다 오류 | 대화만 닫고 안내 + [다시 시도] (`ChatErrorBoundary`) |

문구는 AI 문서 7-9 · 7-10 · 12-4 F8 표를 그대로 씁니다. 문서에 없어 FE가 정한 문구는 코드에 그렇다고 적어 둡니다.

## 8. 시간 · 성능 제약

| 값 | 크기 | 위치 |
|---|---|---|
| 사용 가능 여부 제한 · 재조회 | 5초 · 2/4/8초 | `chatAvailability.ts` |
| 접수 확인 대기 | 15초 | `chatTransport.ts` `SEND_UNCONFIRMED_MS` |
| 요청 하나의 제한 | 20초 | `REQUEST_TIMEOUT_MS` |
| 조회 간격 | 실행 중 1초 · 그 밖 2초 | `POLL_RUNNING_MS` · `POLL_IDLE_MS` |
| 조회 실패 뒤 간격 | 2 → 4 → 8 → 16 → 30초 | `FAILURE_STEPS_MS` |
| 늦어짐 판단 · 그 뒤 간격 | 130초 · 30초 | `SLOW_AFTER_MS` · `SLOW_POLL_MS` |
| 글자 효과 | 50ms마다, 최대 2초 뒤처짐 | `chatTyping.ts` |

- 글자 효과로 채워지는 요소에는 `aria-live`를 두지 않습니다(글자마다 읽힘). 완성된 문장만 따로 둔 `role="status"` 영역에 넣습니다.

## 9. 테스트

| 무엇 | 파일 |
|---|---|
| 화면 동작(보내기 · 조회 · 카드 · 안내 · 복원) | `ChatAgentHost.test.tsx` |

| 브라우저 끝까지(E2E) | `e2e/chat.e2e.ts` — `npm run test:e2e`. 목 서버를 3100 포트에 새로 띄워 돌립니다 |

- 목 서버(`npm run dev`)에서는 `mocks/chat.ts` 맨 위 주석의 문장으로 상황을 고릅니다(예: "날씨" → 거절).
- 실제 BE · AI로는 dev 서버에서 확인합니다. dev BE · AI의 `AGENT_ENABLED`가 켜져 있어야 버튼이 보입니다.

- E2E 시나리오와 시험 수: AI 12-4 F9의 기본 12개 시나리오는 `chat.e2e.ts`에서 22개 시험이며, 패널 반응형·모바일 접근성·스크롤 복원 회귀 시험 6개, 320×400px 낮은 화면의 입력·전송 1개, 기억 첫 안내 최초 노출·재열기 1개를 합쳐 `chat.e2e.ts`에 **30개** 시험이 있습니다. `chat-side-panel-regression.e2e.ts`의 화면별 배치·초안 유지·모달·스크롤 회귀 **18개**까지 포함하면 채팅 관련 Chromium E2E는 **48개**입니다. '기억 없이' 테스트는 생성 전 스위치·배지, 생성 후 배지, 새 대화 초기화, 대화 목록 재선택 시 저장된 `memory_off` 복원까지 검증합니다. CSS 뷰포트 테스트는 실기기 가상 키보드와 브라우저 확대 125~200% 수동 검증을 대체하지 않습니다.
- E2E는 PR마다 CI(`frontend-ci.yml`의 `frontend-e2e` job, Chromium)에서 돕니다. 아직 브랜치 보호의 필수 검사는 아니라 실패해도 머지가 막히지 않으니, PR의 검사 결과를 직접 확인합니다. 로컬에서는 `npm run test:e2e`로 돌립니다.

## 10. 열린 질문 · 알려진 한계

- **기억 첫 안내를 봤는지** — AI 문서(12-1)는 BE가 사용자별로 저장한다고 하지만 BE 응답에 칸이 없습니다. 지금은 브라우저에 두어 다른 기기에서는 한 번 더 보입니다. `chatMemory.ts`의 `(BE 미구현)` 표시.
- **E2E가 필수 검사가 아님** — `frontend-e2e` job은 PR마다 돌지만 브랜치 보호의 필수 검사에는 아직 없습니다. 몇 주 돌려 흔들리지 않으면 BE 담당(`.github/workflows/`)과 함께 필수로 올릴지 정합니다(`frontend-ci.yml` 주석).
