# FE 화면 설계서 명명·분류 규칙

적용 범위: `docs/fe/design/`의 화면 목록, 시안, 문서. 실제 제품의 컴포넌트나 라우트명은 이 문서만을 근거로 변경하지 않는다.

## 이름을 구분하는 기준

- **표시 이름(`title`)**: 사용자가 찾는 기능을 앞에 쓰고, 필요한 경우만 ` · 상태/용도`를 붙인다. 예: *피치 생성 · 수정*, *Take 비교 · 이전 주소*.
- **분류(`group`)**: 담당자나 파일명 대신 사용자 흐름을 기준으로 나눈다. 실제 제품 화면과 별도 검토 시안은 구분한다.
- **상태(`status`)**: 제품 동작을 그린 샘플은 `제품에 있음`, 별도 검토 중인 디자인은 `시안`으로 둔다. 이미 구현된 디자인과 유사한 과거 비교안도 검토 시안으로 유지할 수 있다.
- **화면 ID(`id`)**: `?screen=...` 주소, 화면 이동, 테스트에 쓰는 안정된 값이다. 제목을 바꾸더라도 **기존 ID를 변경하지 않는다**. 특히 `pitch-create-a` · `prepare-mission` · `processing-loading`은 공유 URL 호환을 위해 유지한다.
- **제품 경로(`route`)**: 실제 FE 라우트이거나 시안이 제안하는 경로를 뜻한다. 화면 제목과 별도로 관리한다.

기본 진입 화면은 홈(`screens[0]`)이다. 왼쪽 탐색 목록은 아래 그룹 순서를 따르므로 첫 그룹(기초)과 기본 화면은 다를 수 있다.

## 왼쪽 목록 순서

| 그룹 | 다루는 내용 |
| --- | --- |
| 기초 | 색, 글꼴, 간격, 테두리, 반응형, 문구 |
| 컴포넌트 | 재사용 버튼, 카드, 배지 등 |
| 대화 상자 | 확인, 도움말, 설문 등의 창 |
| 서비스 시작 | 서비스 소개, 로그인 |
| 피치 관리 · 생성 | 홈, 피치 생성·수정 |
| 연습 준비 · 진행 | 시작 전 세팅, 리허설·실전 |
| 분석 · 기록 · 리포트 | 분석 대기, 대본 확인, 업로드 재시도, 리포트, Take 기록·비교 |
| 안내 · 계정 | 설명, 접근 제한, 오류, 마이페이지 |
| 검토 시안 | 제품과 비교하며 검토할 별도 디자인 |

`src/catalog.ts`의 `GUIDE_GROUP_ORDER`가 이 순서를 정한다. 새 그룹은 여기와 목록 순서를 함께 수정한다.

## 정리한 주요 표시 이름

| 이전 표시 이름 | 현재 표시 이름 | 기존 ID |
| --- | --- | --- |
| 발표 준비 A안 · PM 검토 | 피치 생성 · A안 검토 시안 | `pitch-create-a` |
| 시작 전 세팅 · PM 검토 시안 | 시작 전 세팅 · 배치 검토 시안 | `prepare-layout-review` |
| 리허설 무대 | 리허설 · 실전 | `stage` |
| 이전 Take 비교 주소 | Take 비교 · 이전 주소 | `comparison` |
| 무대를 열지 않는 안내 | 리허설 · 접근 안내 | `stage-blocked` |
| 미지원 브라우저 | 미지원 환경 안내 | `unsupported` |
| 웰컴 · 서비스 소개 | 서비스 소개 · 시작하기 | `welcome` |

**`comparison`은 별도 신규 비교 화면이 아니라 기존 주소를 보존하는 호환 항목**이다. 실제 지표 비교는 Take 기록의 전환 화면에 있다. 중복처럼 보여도 링크 호환 여부를 확인하기 전에는 삭제하지 않는다.

## 파일과 문서 이름

- `src/screens/`: 화면 하나면 `<Feature>Screen.tsx`, 함께 정의한 여러 화면이면 `<Feature>Screens.tsx`.
- `src/ui/`: 재사용 컴포넌트는 PascalCase, 검토 시안에서만 쓰는 컴포넌트는 대상 시안 접두어를 둔다(예: `PrepareDraftAudioMeter.tsx`).
- `src/components/`와 `src/foundations/`: 각각 컴포넌트 사용법과 디자인 기초를 관리한다.
- Markdown: 소문자 kebab-case로 기능·목적을 나타낸다. `README.md`는 진입 안내, `audit.md`는 제품 대조, `prepare-layout-review.md`는 특정 검토안 결정 기록이다.
- 테스트: 대상 파일명에 `.test.ts` 또는 `.test.tsx`를 붙인다.

이번 정리는 **목록 명칭과 문서 구조만 정리**한다. 기존 `CreateConceptScreen.tsx`, `PrepareLayoutDraft.tsx`, `AnalysisScreen.tsx`처럼 이미 import와 테스트에 연결된 파일명은 무리하게 변경하지 않는다. 추후 파일명을 바꿀 때는 모든 import·CSS 참조·테스트·문서 링크를 함께 수정한다.

## 유지·검증 규칙

1. 화면을 추가·수정하면 `src/catalog.ts`의 제목, 그룹, 상태, 규칙, `productNote`를 확인한다.
2. 새 화면은 `src/ScreenPreview.tsx`에 연결한다. 기존 `screen` · `state` ID가 포함된 링크를 보존한다.
3. 실제 제품이 바뀌면 `audit.md`의 제품 대조 절차를 적용한다. **제목과 그룹만 바꾼 작업은 `PRODUCT_CHECKED`를 갱신하지 않는다.**
4. `npm run typecheck` · `npm run lint` · `npm run test` · `npm run format:check`로 확인한다.
