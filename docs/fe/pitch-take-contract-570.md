## PR 전체 검토에서 수정한 문제

- 종료 시각에서 발표 길이를 빼 시작 시각을 만들면 새로고침·정지 구간에 따라 최초 시작 시각이 바뀝니다. `started_at`을 전송하지 않아 서버 기록을 보존합니다.
- 저장 요청과 재정리가 겹친 뒤 빈 버전을 만들면 서버 응답과 같은 번호가 중복될 수 있습니다. 같은 번호의 빈 버전은 서버 결과로 교체합니다.
- 정리 요청 중 대본·슬라이드 화면으로 이동하면 늦은 응답이 화면 또는 선택 버전을 바꿀 수 있습니다. 요청 후 이동한 화면의 선택을 유지합니다.
- 저장 중 표시 버전이 바뀌면 응답이 현재 표시된 버전에 연결될 수 있습니다. 요청 시점의 원본 버전 번호를 mutation 변수에 담습니다.

단일 브라우저에서 여러 비동기 요청이 겹치고 응답 순서가 바뀌는 경우를 포함해 검토했습니다. 위 문제는 저장소 상태 테스트와 컴포넌트 회귀 테스트로 확인했습니다.
