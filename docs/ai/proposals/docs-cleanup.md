# 제안: AI 기준 문서를 실무 기술문서로 정리하기

> **이 문서는** `docs/ai/`의 기준 문서 12개(공통 3 · 기능 9)를 AI 시니어 개발자가 구현 · 운영에 쓰는 실무 기술문서로 정리하는 기준 · 결정 · 순서 · 검증을 정한다. 문서마다 바꿀 곳은 8절(공통 문서)과 9절(기능 문서)에 절 단위로 있고, DB 설계 담당 문장의 전 → 후는 7절에 있다.
> **한 줄 요약**: 계약 · 규칙 · 실행 · 운영은 남기고 PR 번호 · 작업 이력 · 기초 설명 · 중복 · 코드와 다른 서술을 정리한다. DB 저장은 "AI는 입출력과 저장 요구, 테이블 · 칸 설계는 BE"로 바꾼다. 절 번호와 계약의 뜻은 그대로 두고, 문서 하나씩 PR로 고친다.
> **상태**: 최종안. 기준 문서 12개 정리는 JWK0395가 모두 고치는 것으로 팀 확인을 받았다(각 PR은 그 문서 담당이 리뷰). `architecture.md`의 계약 문장은 수정 규칙대로 Issue 결정 댓글을 남긴다.

# 0. 기준
**읽는 사람**: 이 저장소의 AI 기능을 구현 · 운영하는 개발자. 일반 개념은 안다고 본다.

**남길 것**
- 계약: 입출력 필드 · 예시 · 오류 코드 · 시간 예산 · 버전 · 호출 시점
- 처리 규칙 · 실패 처리, 짧은 설계 이유(왜 이 값 · 이 방식인지 한두 문장)
- 실행 · 시험 · 배포 · 운영 절차와 명령
- 저장 요구, 품질 검증 방법 · 지표 정의, 열린 질문 · 한계(짧게), 확정 값 표

# 1. 지킬 것
- **절 번호를 바꾸지 않는다.** 기능 문서의 절 번호 0~16 틀과 하위 절(5-2 등), `ai-service.md` · `architecture.md`의 절 번호를 서비스 코드 · BE · FE 코드 주석과 문서가 약 550곳에서 가리킨다(`ai/service` 233 · `backend` 126 · `frontend` 76 · `ai/research` 75 · `ai/tools` 30 · 그 밖). 절을 비우게 되면 제목은 두고 "해당 없음" 또는 가리키는 곳을 적는다.
- **계약의 뜻을 바꾸지 않는다.** 필드 · 값 · 의미 · 호출 시점은 그대로다. 바뀌는 것은 D(누가 저장 설계를 하는지와 그 서술 형식)뿐이다.
- **지켜지는 저장 계약은 유지한다.** 유일 제약 · 덮어쓰기 막기 · 보관 · 삭제 조건처럼 지금 BE가 지키는 조건은 저장 요구로 옮겨 그대로 둔다.
- 예시 JSON · 표 · 명령은 줄여도 계약 값은 남긴다.

AI 문서에서 "AI 기능 결과의 DB 저장 설계(테이블 · 칸 · 형식)는 AI가 정한다"고 적힌 16곳(`architecture.md`에서 4곳 · `ai-service.md`에서 2곳 · 기능 문서 12-1 첫 문장 9곳 · `coach-agent.md`의 '정한 값' 1곳)을 "AI는 입력 · 출력과 저장 요구만, 테이블 · 칸 설계는 BE"로 바꾸는 문장이다. 코드는 바뀌지 않는다. 지금 지켜지는 저장 계약(유일 제약 · 덮어쓰기 막기 등)은 따로 합의해 바꾸기 전까지 그대로 유효하다. 이 16곳은 2절 J1의 D에 들어가고, J1이 기능 문서 12-1 표 등으로 범위를 넓힌다(8 · 9절). `architecture.md` · `ai-service.md`의 담당 문장은 BE가 하는 일이 바뀌므로 BE와도 합의하고 BE를 리뷰어로 넣는다.

## 7-0. 왜 바꾸나
- BE가 "AI가 테이블 · 칸까지 정하지 말고 입력 · 출력만 정해 주면 BE가 알아서 하는 편이 낫다"고 요청했다.
- 지금 문서는 AI가 저장 설계를 하고 BE는 마이그레이션 · 구현만 한다고 적혀 있다. 실제로 테이블 · 칸을 만들고 운영하는 쪽은 BE라서, 설계 결정도 BE가 하는 편이 맞다.
- 다만 AI가 손을 떼면 안 되는 것이 있다. **무엇을 남겨야 하는지, 무엇과 이어야 하는지, 얼마나 두는지, 언제 지우는지, 무엇을 덮어쓰면 안 되는지**(저장 요구)는 AI 기능이 제대로 돌기 위한 계약이다. 이것은 AI가 계속 정한다.

| 지금 | 바뀐 뒤 |

| AI: 무엇을 · 어느 테이블 · 칸에 · 어떤 형식으로 저장할지 정함 | AI: 입력 · 출력과 **저장 요구**(무엇을 남기고 · 무엇과 잇고 · 얼마나 두고 · 언제 지우고 · 무엇을 덮어쓰면 안 되는지)를 정함 |
| BE: 마이그레이션 · 구현 · 운영 | BE: **테이블 · 칸 · 형식** · 마이그레이션 · 구현 · 운영 |
| 저장 모양도 계약(바꾸면 계약 변경) | 저장 요구가 계약(바꾸면 계약 변경). 이미 정해 둔 저장 계약은 따로 합의해 바꾸기 전까지 유효 |

# 9. 기능 문서 변경 목록
기능 문서(`docs/ai/features/`의 9개)마다 바꿀 곳을 절 단위로 적는다. 분류 코드와 기준은 0절, 결정은 2절이다.
