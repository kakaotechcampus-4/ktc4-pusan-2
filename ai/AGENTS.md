# AI 작업 안내

## 먼저 읽을 문서
- `ai/` 또는 `docs/ai/`를 개발·검토할 때 `docs/ai/README.md`를 먼저 읽는다. 문서 지도·담당·현재 상태·수정 규칙의 기준이다.
- `docs/ai/architecture.md` 0·1절에서 전체 흐름을 보고, 맡은 기능 문서 0·3·5절과 필요한 절을 읽는다.
- 서비스 구성·실행·기능 탑재 작업은 `docs/ai/ai-service.md` 0절의 역할별 표에서 읽을 절을 찾는다.
- 경로는 저장소 루트 기준이다. 지금 폴더가 하위 폴더면 루트를 찾아 경로를 맞춘다.

## 개발과 검토
- 기능 상태와 실제 폴더·파일을 확인한다. 문서는 목표 설계, 코드는 현재 동작이므로 차이를 먼저 설명한다.
- 설계만 있는 기능을 문서에 맞추려고 마음대로 구현하지 않는다. 요청받은 개발 범위와 계약을 확인하고 구현한다.
- 공통 계약은 `architecture.md`가 기준이다. 다른 문서와 충돌하면 해당 절·문장과 영향을 적어 수정 규칙의 절차로 제안한다.
- 수정 전에 README의 '수정 규칙'으로 영향 범위와 담당을 확인한다. 합의가 필요한 변경은 합의 Issue·결정 댓글·사람이 확정한 계약 문장과 승인 범위를 확인한 뒤 반영한다.
- 검토·제안에는 기준 문서의 절 번호, 근거 코드의 `파일:줄`, 기대 동작·현재 동작, 영향과 확인 방법을 적는다. 코드가 없으면 없다고 적는다.
- 담당이 다른 기능 문서·코드는 직접 고치지 않고 기능 이름·문서 절 번호·필요한 변경을 담은 Issue 초안을 사람에게 넘긴다.
- BE·FE·인프라 변경은 해당 담당에게 요청한다. 저장소 루트의 담당 경계와 `architecture.md` 13절을 확인한다.
- 승인된 계약과 실제 코드가 다르면 이번 작업 범위인지 확인한다. 범위 밖 구현이나 계약 변경을 임의로 추가하지 않는다.
- `ai/archive/`는 동결본이다. 수정·삭제하지 않고 새 작업은 `ai/research/` 또는 `ai/service/`에서 한다.

## 확인 명령
- 바꾸는 기능의 연구 폴더 README·`pyproject.toml`에서 실행 환경과 테스트를 확인한다. 폴더가 없으면 실행했다고 보고하지 않는다.
- Python 명령은 해당 폴더의 `.venv` Python으로 실행한다. Windows 연구 폴더의 예시는 `.\.venv\Scripts\python.exe -m pytest -m "not live"`다. 서비스는 README의 `uv run python -m pytest -m "not live"`를 쓴다.
- 시선 브라우저 코드는 `ai/research/gaze-tracking/web/README.md`의 검증 명령을 쓴다.
- 실제 LLM·실험·노트북은 README에서 과금과 실행 범위를 확인한 뒤 요청 범위에 맞게 실행한다. `.env`의 비밀값은 출력·커밋하지 않는다.
- 커밋한 문서는 루트에서 `python ai/tools/docs-check/check.py --base <PR-base-ref> --head HEAD --pr-body-file <PR본문파일>`로 검사한다. 검사한 head와 미커밋 변경을 보고한다. 도구가 없으면 경로·절을 직접 확인하고 미구현이라고 보고한다.
- 결과에는 실행 위치·명령·성공/실패·실행하지 못한 범위를 적는다. 계약·담당·합의 판단을 검사 도구의 통과만으로 대신하지 않는다.
