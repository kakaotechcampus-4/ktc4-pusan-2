# reader-review — 사람이 읽듯 대화를 보는 검토 (보정 전 보조 검토)

코드 채점 · 근거성 판정이 잡지 못하는 '맞지만 헷갈리는 답'을 찾으려고, 사용자 화면에 보이는 그대로의 대화를 검토 모델이 [`CRITERIA.md`](CRITERIA.md)의 7항목으로 읽는다(Issue #1194). 사람 판정과 맞춰 보기 전에는 수치로 내세우지 않는다.

| 파일 | 하는 일 |
|---|---|
| `CRITERIA.md` | 검토 기준(검토 전에 고정) |
| `RESULTS.md` | 돌린 검토의 요약: 대상 · 검토 모델 · 횟수 · 항목별 `아니오` 수 · 찾은 문제와 고친 곳 · 두 모델 일치 |

## 돌리는 법
1. 대화 기록: 평가 실행을 `chat_agent_lab.transcripts`로 돌리면 결과 폴더에 `transcripts.jsonl`이 생긴다(채점은 `evals`와 같다).
   ```bash
   .venv/bin/python -m chat_agent_lab.transcripts --dir evals/path --set all --workers 4 --search hybrid --out outputs/evals/<이름>
   ```
2. 검토: 대화를 화면 모양 글로 바꿔 검토 모델에 3개씩 묶어 보낸다. 고치기 전후 대화는 섞고 어느 쪽인지 알리지 않으며, 구현 맥락은 주지 않는다. 검토 모델은 항목마다 `예` · `아니오` · `해당 없음`과 근거 인용을 JSON 으로 돌려준다.
3. 결과는 `RESULTS.md`에 요약한다. 상세(대화 · 판정)는 결과 폴더에 둔다(git 무시).

## 하지 않는 것
- 숫자 · 근거 대조(코드 채점의 몫), 발표법 조언의 옳고 그름(근거성 판정의 몫).
- 독립 평가 v2 공식 점수에 넣기(v2 는 채점기까지 동결했다).
