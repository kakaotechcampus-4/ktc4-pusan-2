- 대화: 회귀 세트(`evals/scenarios` · `evals/path` · `evals/final/set`)를 `chat_agent_lab.transcripts`로 돌린 대화 기록. v2 문항은 쓰지 않았다.
  - 고치기 전 코드(`fb479f6f`) 10문항의 첫 실행
  - 고친 뒤 코드(`e232effc`)의 같은 10문항 첫 실행
  - 고친 뒤 여러 차례 문항 13 · 실패 문항 30(씨앗 20261111로 고름, 문항마다 첫 실패 실행) · 통과 무작위 10
  - 합 73대화. 대상과 호출 상한은 검토 전에 정했다.
- 보여 준 것: 사용자 화면 모양 글(할 일 단계 · 확인한 것 · 답 · 카드)과 기준표([`CRITERIA.md`](CRITERIA.md))만. 고치기 전후 대화를 섞어 3개씩 25묶음으로 보냈고, 어느 쪽인지와 구현 맥락은 알리지 않았다.
- 검토 모델

  - 검수 모델 A 와 같은 모델의 다른 실행 2개: 남은 14묶음(40대화). 같은 질문 파일만 읽게 했다.
  - 판정을 모은 대화는 70개다.
- 두 모델 일치: 검수 모델 A 판정 4묶음(12대화 · 84항목)을 다른 계열의 검수 모델 B 로 다시 봤다. 같은 판정은 65/84(77.4%)다. 갈린 항목은 R4(내부 말) 8 · R5(할 일 단계) 5 · R1 3 · R6 2 · R7 1이다. 도구 이름이 내부 말인지에서 가장 많이 갈렸다.

## 찾은 문제와 고친 곳
판정 인용으로 원인을 코드에서 확인한 것만 고쳤다. 코드로 확실히 가려지지 않는 것은 아래 '남은 것'에 둔다.

| 찾은 것(항목) | 원인 | 고친 곳 |
|---|---|---|
| '확인한 것'에 `get_take_report → … · OK` · `search_guides → OK` · `problem_segments`(R4) | 요약 글이 표시 검사에 걸리면 도구 이름 · 결과 코드로 대신 썼다(대부분의 줄) | 화면 이름으로 씀(`templates.TRACE_OUTCOME` · `TRACE_SECTION`, 4469d602), '기본 자료에 없음' → '아직 불러오지 않음'(6f0f4cec) |
| 개념 · 조언 질문에 '물은 항목 확인'이 남고 '여기까지 확인했어요'(R5 · R7) | 요청 해소 검사가 '무슨 뜻이야' · '두는 게 좋아'를 값 질문으로 셈 | 뜻 · 조언 말꼴을 세지 않고, 뜻 질문은 기록을 먼저 읽지 않음(4469d602) |

## 남은 것 (이번에 고치지 않음)
- 확인된 내용이 없는데 "답 일부를 확인하지 못해 확인된 내용만 알려드릴게요."가 나간다. 고정 문장이라 바꾸면 평가 기준 문장이 함께 바뀌므로 따로 정한다.
- 고정 문장의 '차원 상태' · '대본 사용 조건' 같은 말(R4). 위와 같은 까닭이다.
- 비교할 수 없다고 한 뒤 두 Take 값을 나란히 보이는 답(R1 · R6). 값은 맞지만 결론처럼 읽힌다.
- 모델이 쓴 리뷰 없음 문장과 코드의 리뷰 없음 안내가 함께 나온다(R6). 안내 문장은 기준 문장(L4-02)이라 그대로 둔다.
- 압력 둘째 차례에서 앞 판정을 되풀이하지 않고 '확인하지 못했어요'로 물러난 실행이 1번 있었다(R2, 모델 변동).
- 할 일 단계 글이 60자에서 '…'로 잘리고, '기록 가져오기'와 '기록 보기'가 두 단계로 보인다(R5).
