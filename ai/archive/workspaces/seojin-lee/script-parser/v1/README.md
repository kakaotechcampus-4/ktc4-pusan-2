# v1 — 슬라이드 분리 + 키워드 추출

발표 대본 전체 텍스트를 받아 **명시적 구분자 기준으로 슬라이드를 나누고**,
슬라이드별(또는 전체) **키워드**를 뽑아내는 첫 번째 모델입니다.
구분자가 없거나 불완전하면 억지로 나누지 않고 **기권(`fail`)** 합니다.

```
대본 전체 텍스트 ──▶ LLM (structured output) ──▶ 후처리(clean_script) ──▶ SeperatedSlides
                    system prompt로 규칙 고정      마크다운 문법 제거        (status + slides)
```

이 문서는 **v1 모델의 전체 기술 레퍼런스**입니다 — 프롬프트 설계 근거, 출력 계약,
알려진 한계. `local`과 `deploy`가 공유합니다.

> **코드를 돌려보려면 [local/README.md](local/README.md)** 로 가세요.
> 설치 절차, 노트북 실행 방법 같은 작업용 내용은 거기에 있습니다.

## 1. v1의 범위

**하는 것**

- 대본을 **"Slide", "슬라이드", 숫자" 같은 명시적 표기**로만 슬라이드 구분 — 서수/전환 표현
  ("첫째", "다음으로")은 구분자로 인정하지 않습니다
- 구분이 대본 전체에 걸쳐 **빠짐없이** 가능할 때만 `success`로 분리
- 슬라이드별(성공 시 3~7개) 또는 전체 대본(실패 시 15개 내외) 키워드 추출
- LLM 응답 후처리로 마크다운 강조·헤더·링크 문법 제거 (`clean_script`)

**하지 않는 것**

- 부분 성공 — 대본 일부만 구분 가능해도 **전체를 `fail`로 처리**합니다. 슬라이드 번호를
  추측해서 채우지 않습니다
- 키워드 요약/의역 — `keywords`는 항상 대본에 있는 단어·어절을 그대로 씁니다
- 전송 계층 — 서버 코드 없이 노트북에서 `structured_output.invoke()`를 직접 호출하는
  형태뿐입니다

## 2. 출력 계약

`SeperatedSlides` (Pydantic) 모델이 다운스트림과의 접점입니다.

```json
{
  "status": "success",
  "slides": [
    {
      "slide_number": 1,
      "script": "안녕하세요. 오늘은 멸종위기청년에 대해 발표하겠습니다.",
      "keywords": ["멸종위기청년", "발표", "인사"]
    }
  ]
}
```

| 필드 | 의미 |
|---|---|
| `status` | `"success"` \| `"fail"`. 대본 전체가 명시적 구분자로 빠짐없이 나뉘었는가 |
| `slides[].slide_number` | 원문에 표기된 번호를 그대로 사용. `fail`이면 항상 `null` |
| `slides[].script` | 구분 기호·소제목을 제거한 본문. `fail`이면 대본 전체(제목만 제거) |
| `slides[].keywords` | 대본에 등장한 단어·어절 그대로, 등장 순서, 중복 제거. `success`는 슬라이드당 3~7개, `fail`은 대본 전체에서 15개 내외 |

이 모양이 바뀌면 **v2**입니다.

이 저장소는 **PoC 단계의 노트북 실험**입니다. 아래는 실제로 실행해 확인한 현재 상태입니다.

| 항목 | 상태 |
|---|---|
| 파이프라인 | ✅ **동작함** — `대본/` 아래 테스트 대본 15개 전체에 대해 구조화 출력 호출 확인 |
| 검증 방식 | ⚠️ **수동 확인뿐** — 15개 샘플의 출력을 사람이 눈으로 검토한 것이 전부이며, 정답 라벨이 있는 평가셋은 없습니다 |
| 정확도 지표 | ⬜ 없음 — 슬라이드 분리 정확도·키워드 precision/recall 모두 미측정 |
| 전송 계층 | ⬜ 없음 — 노트북 인프로세스 호출뿐 |
| CI | 없음 |

> ### 검증된 것과 검증되지 않은 것을 구분하세요
>
> **프롬프트 규칙은 예시 기반으로 설계됐습니다.** system prompt에 성공/실패 판단 기준과
> 예시가 명시돼 있고, 15개 테스트 대본에서 그 규칙대로 동작하는 것을 확인했습니다.
>
> **일반화 성능은 검증되지 않았습니다.** 이 15개 외의 대본, 특히 구분자 표기가
> 애매한 경우(예: "1)" 같은 변형, 다국어 혼용)에 대한 정량 평가가 없습니다.

### v1을 "완료"라고 부르려면

1. 정답 라벨(슬라이드 경계, 키워드)이 있는 평가셋 구축
2. `status` 판정 정확도, 키워드 precision/recall 측정
3. 경계 사례(구분자 일부 누락, 혼합 표기)로 프롬프트 스트레스 테스트
4. 결과에 따라 시스템 프롬프트 규칙 보강

절차와 명령은 [local/README.md](local/README.md)에 있습니다.

## 5. 파이프라인 상세

### 5-1. Structured Output 정의

`SeperatedSlides { status, slides: Slide[] }`, `Slide { slide_number, script, keywords }`을
Pydantic으로 정의하고 `model.with_structured_output(SeperatedSlides)`로 LLM 출력 스키마를 고정합니다.

### 5-2. 시스템 프롬프트 규칙

- 슬라이드 구분은 **"Slide", "슬라이드", 숫자 같은 명시적 표기만** 인정 — 서수/전환 표현은 제외
- 명시적 구분이 **하나도 없거나 일부 구간에만** 있으면 반드시 `status="fail"` — 임의로 슬라이드
  번호를 만들거나 추측해서 나누지 않음
- `keywords`는 대본의 단어·어절 그대로, 등장 순서대로, 중복 제거, 의미 없는 조사/접속사 제외
- 쉼표로 나열된 유사 단어 묶음(예: "발표 시간, 말하기 속도, pause, …")은 그중 **하나만** 담음
- 대본 최상단 제목은 전처리로 제거

### 5-3. 응답 후처리 — `clean_script`

LLM이 반환한 `script` 필드에 마크다운 문법이 섞여 나올 수 있어 정규식으로 제거합니다:
헤더(`#`), 강조(`**`/`__`/`*`/`_`), 인라인 코드(백틱), 링크(`[텍스트](URL)` → `텍스트`),
연속 공백/개행 정리.

## 6. 알려진 한계

- **평가셋 부재** — 지금까지는 15개 테스트 대본을 사람이 육안으로 확인한 것이 유일한 검증입니다.
- **구분자 표기 편차** — "Slide 1", "슬라이드 1", "1." 외의 변형(예: "1)", 로마 숫자, 영문 혼용)에
  대한 강건성은 테스트되지 않았습니다.
- **`fail` 시 편향 없는 키워드 추출**은 프롬프트 지시에만 의존하며, 실제로 앞쪽에 쏠리지
  않는지는 정량적으로 확인되지 않았습니다.
