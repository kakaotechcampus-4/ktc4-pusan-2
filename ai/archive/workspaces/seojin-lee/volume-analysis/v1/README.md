# v1 — 캘리브레이션 기반 발표 음량 판정 (low / normal / high)

사전 캘리브레이션 값(주변 소음·평소 목소리)과 발표 중 현재 음량을 받아 **음량 지표 세 가지**를
계산하고, 임계값과 비교해 음량이 적절한지 판정하는 첫 번째 모델입니다. LLM 호출 없이
**규칙 기반(임계값 비교)**으로만 판정합니다.

```
캘리브레이션                         지표 계산                        임계값 비교
{noise_db, baseline_voice_db} ─┐
                                ├──▶ current / relative /  ──▶ 절대 판정 (low/normal/high)
발표 중 current_db ────────────┘      baseline_difference       상대 판정 (low/normal)
```

이 문서는 **v1 모델의 전체 기술 레퍼런스**입니다 — 계산 방식, 출력 계약, 알려진 한계.
`local`과 `deploy`가 공유합니다.

> **코드를 돌려보려면 [local/README.md](local/README.md)** 로 가세요.
> 설치 절차, 노트북 실행 방법 같은 작업용 내용은 거기에 있습니다.

## 1. v1의 범위

**하는 것**

- 사전 테스트에서 측정한 **주변 소음(`noise_db`)**과 캘리브레이션에서 측정한
  **평소 목소리 음량(`baseline_voice_db`)**을 `Calibration`으로 받음
- 발표 중 측정된 **현재 음량(`current_db`)**으로 세 가지 지표 계산
  - `current_db` — 절대 음량
  - `relative_db = current_db - noise_db` — 주변 소음 대비 음량
  - `baseline_difference_db = current_db - baseline_voice_db` — 평소 목소리 대비 변화
- 절대 음량을 두 임계값(`ABSOLUTE_LOW=60`, `ABSOLUTE_HIGH=75`)과 비교해 `low`/`normal`/`high` 판정
- 상대 음량을 임계값(`RELATIVE_LOW=10`)과 비교해 `low`/`normal` 판정

**하지 않는 것**

- 오디오 신호에서 dB 추출 — 입력은 이미 측정된 dB 값이라고 가정 (측정은 FE 담당)
- 두 판정을 합친 **최종 판단** — 아직 설계하지 않았습니다
- `baseline_difference_db`를 이용한 판정 — 지표만 계산하고 판정에는 쓰지 않습니다
- 시간 축 처리(구간 평균, 스무딩, 연속 N초 이상 작을 때만 경고 등) — 단일 값 하나씩만 판정
- 전송 계층 — 서버 코드 없이 노트북 셀을 직접 실행하는 형태뿐입니다

## 2. 출력 계약

`VolumeMeasurement` (Pydantic) 모델이 현재 정의된 출력입니다.

```json
{
  "current_db": 58.0,
  "relative_db": 13.0,
  "baseline_difference_db": -7.0
}
```

| 필드 | 의미 |
|---|---|
| `current_db` | 발표 중 현재 측정된 음량(dB). `float` |
| `relative_db` | `current_db - noise_db`. 주변 소음보다 몇 dB 크게 말하는가. `float` |
| `baseline_difference_db` | `current_db - baseline_voice_db`. 음수면 평소보다 작게, 양수면 평소보다 크게 말하는 중. `float` |

판정 함수의 반환값:

| 함수 | 입력 | 반환 |
|---|---|---|
| `judge_absolute_volume` | `current_db` | `"low"` (< 60) \| `"normal"` \| `"high"` (> 75) |
| `judge_relative_volume` | `relative_db` | `"low"` (< 10) \| `"normal"` |

> ⚠️ **이 계약은 잠정입니다.** 판정 결과를 담는 스키마(예: `VolumeResult`)는 아직 없고,
> 두 판정 함수는 문자열만 반환합니다. 최종 판단 방식이 정해지면 출력 모양이 바뀔 수 있습니다.

---

이 저장소는 **PoC 단계의 노트북 실험**입니다. 아래는 실제로 실행해 확인한 현재 상태입니다.

| 항목 | 상태 |
|---|---|
| 지표 계산 | ✅ **동작함** — 예시 캘리브레이션(소음 45 dB, 목소리 65 dB)에 대해 50~80 dB 7개 값으로 세 지표 확인 |
| 판정 함수 | ✅ **동작함** — 예시 값 58 dB에 대해 `relative_db=13.0`, `baseline_difference_db=-7.0`, 절대 `low`, 상대 `normal` 확인 |
| 검증 방식 | ⚠️ **수동 확인뿐** — 손으로 넣은 예시 값을 사람이 눈으로 검토한 것이 전부이며, 정답 라벨이 있는 평가셋은 없습니다 |
| 임계값 근거 | ⬜ 없음 — `ABSOLUTE_LOW/HIGH`는 "논문 및 테스트 데이터를 바탕으로 수정", `RELATIVE_LOW`는 "실제 기준 조사 후 수정" 예정인 임시값입니다 |
| 최종 판단 로직 | ⬜ 없음 — 여러 지표를 확인하며 평가 방법을 찾는 단계 |
| FE와 dB 수치 합의 | ⬜ 논의 전 — dB 측정 방식·스케일이 정해져야 임계값이 의미를 가집니다 |
| 전송 계층 | ⬜ 없음 — 노트북 셀 직접 실행뿐 |
| CI | 없음 |

> ### 검증된 것과 검증되지 않은 것을 구분하세요
>
> **지표 정의와 판정 함수는 동작합니다.** 캘리브레이션 대비 차이를 계산하고, 임계값으로 등급을
> 나누는 로직이 예시 값에서 기대대로 나옵니다.
>
> **임계값·지표 선택·dB 스케일은 검증되지 않았습니다.** 60/75/10이라는 경계값, 어떤 지표를
> 최종 판단에 쓸지, FE가 측정하는 dB가 어떤 기준(dBFS/dB SPL 등)인지 모두 정해지지 않았습니다.
> 특히 dB 스케일이 다르면 절대 음량 임계값(60/75)은 그대로 쓸 수 없습니다.

### v1을 "완료"라고 부르려면

1. FE와 dB 측정 방식·스케일·측정 주기 합의
2. 실제 발표 음량 데이터(정답 라벨 포함)로 임계값 설정·검증
3. 절대/상대/캘리브레이션 대비 지표 중 최종 판단에 쓸 조합과 결합 규칙 확정
4. 판정 결과 스키마(예: `VolumeResult`) 정의 및 반환하도록 코드 정리

절차와 명령은 [local/README.md](local/README.md)에 있습니다.

## 5. 파이프라인 상세

### 5-1. 데이터 구조

```
Calibration       { noise_db: float, baseline_voice_db: float }
VolumeMeasurement { current_db: float, relative_db: float, baseline_difference_db: float }
```

### 5-2. 캘리브레이션

발표 시작 전 두 번 측정합니다.

| 값 | 언제 | 예시 |
|---|---|---|
| `noise_db` | 사전 테스트 — 사람이 말하지 않을 때의 주변 소음 | 45.0 |
| `baseline_voice_db` | 캘리브레이션 — 사용자가 평소 목소리로 말할 때 | 65.0 |

`baseline_voice_db - noise_db`(예시 20 dB)는 사용자의 평소 목소리가 주변 소음보다 얼마나 큰지를
보여주며, 상대 음량 임계값을 정할 때 참고할 수 있습니다.

### 5-3. 지표 계산

```
relative_db            = current_db - noise_db             ← 주변 소음 대비
baseline_difference_db = current_db - baseline_voice_db    ← 평소 목소리 대비
```

예시 캘리브레이션(소음 45, 목소리 65) 기준 테스트 결과:

| current_db | relative_db | baseline_difference_db |
|---|---|---|
| 50 | 5 | -15 |
| 55 | 10 | -10 |
| 60 | 15 | -5 |
| 65 | 20 | 0 |
| 70 | 25 | 5 |
| 75 | 30 | 10 |
| 80 | 35 | 15 |

### 5-4. 임계값 판정

```
절대 음량 (current_db)
  current_db < ABSOLUTE_LOW(60)   → "low"
  current_db > ABSOLUTE_HIGH(75)  → "high"
  그 외                            → "normal"

상대 음량 (relative_db)
  relative_db < RELATIVE_LOW(10)  → "low"
  그 외                            → "normal"
```

두 판정은 서로 독립이며, 같은 입력에서 다른 결과가 나올 수 있습니다
(예: 58 dB → 절대 `low`, 상대 `normal`). 둘을 어떻게 합칠지는 아직 정하지 않았습니다.

## 6. 알려진 한계

- **임계값 근거 없음** — 60/75/10은 임시값이며, 논문·실측 데이터로 검증되지 않았습니다.
- **dB 스케일 미정** — FE가 측정하는 dB의 기준이 정해지지 않아, 특히 절대 음량 판정은
  환경(마이크·기기·게인)에 따라 의미가 달라질 수 있습니다.
- **최종 판단 없음** — 절대/상대 판정이 따로 나올 뿐 하나의 결론으로 합쳐지지 않습니다.
- **상대 음량은 `high`가 없음** — 상대 판정은 너무 작은 경우만 잡고, 너무 큰 경우는 판정하지 않습니다.
- **캘리브레이션 대비 지표 미사용** — `baseline_difference_db`는 계산만 하고 판정에 쓰지 않습니다.
- **단일 값 판정** — 시간 축 처리(구간 평균, 순간 피크 무시 등)가 없어 실시간 입력에서는
  판정이 크게 흔들릴 수 있습니다.
- **예시 값뿐** — 실제 발표 음량 측정 데이터에 대한 검증은 없습니다.
