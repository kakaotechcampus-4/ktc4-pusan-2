## 이 워크스페이스의 규칙

### 버전 축이 두 개입니다

헷갈리기 쉬우니 먼저 짚습니다.

| | 무엇 | 어디서 올라가는가 |
|---|---|---|
| **모델 버전** (`v1`, `v2`, …) | 모델의 **출력 의미**가 바뀔 때 | `workspaces/jewon-kim/<project>/vN/` |
| **릴리스 버전** (`v1.0.0`, …) | 제품으로 묶어 내보낼 때 | `releases/vX.Y.Z/<project>/` |

둘은 독립입니다. 모델 `v1`이 릴리스 `v1.0.0`과 `v1.1.0`에 모두 실릴 수 있고,
반대로 모델 `v2`를 만드는 동안 릴리스는 계속 `v1`을 내보낼 수도 있습니다.

**모델 버전을 올리는 기준**: 백본 교체, 클래스 정의 변경, 캘리브레이션 방식 변경처럼
**소비자가 받는 이벤트의 의미가 달라지는** 변화. 설정값 튜닝이나 임계값 스윕은
버전을 올리지 않습니다 — 그건 각 프로젝트가 기록하는 config hash가 추적합니다.

### `local` / `deploy`

같은 모델을 **어디서 돌리느냐**입니다. 모델 자체는 하나이므로, 두 환경은
`vN/README.md`(모델 기술 레퍼런스)를 공유하고 환경별 README만 따로 둡니다.

- `local/` — 실험·평가 리그. 웹캠을 붙이고, 데이터셋을 만들고, 지표를 재는 곳
- `deploy/` — 서비스 투입용 패키징

### 문서 규칙

각 레벨의 `README.md`가 맡는 범위:

| 레벨 | 답해야 하는 질문 |
|---|---|
| `<project>/README.md` | 이 프로젝트가 무엇이고, 어느 버전이 있고, 어디서 시작하나 |
| `<project>/vN/README.md` | 이 모델이 무엇을 보장하고 무엇을 보장하지 않는가 (**전체 기술 레퍼런스**) |
| `<project>/vN/local/README.md` | 어떻게 돌리고 어떻게 개발하나 (셋업·명령·함정) |

## 환경변수

`gaze-tracking`이 읽는 환경변수입니다. 루트 `.env.example`에 반영이 필요하면 여기를 참고하세요.
**둘 다 선택**이며, 없어도 기본 동작합니다.

| 변수 | 효과 |
|---|---|
| `PITCHCOACH_FORCE_CSV` | `1`/`true`/`yes`면 parquet 엔진이 있어도 gzip CSV로 특징 테이블을 저장. 첫 호출에서 캐시되므로 테이블 조작 전에 설정해야 합니다 |
| `PITCHCOACH_GIT_COMMIT` | 실험 기록에 남는 `code_commit` 값을 덮어씁니다. 커밋을 물어볼 git이 없는 환경(컨테이너·휠)용이며, **빌드에서 설정**해야 합니다 — 손으로 넣으면 기록이 거짓말을 시작합니다 |
